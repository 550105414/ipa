# 密码库同步：原生密钥计算修复

目标版本：iOS 1.6.0 build14；Android 1.6.0 build16。

## 现场依据与边界

2026-10-29 的同步请求中，Android 一次读取到上传之间相隔约 187 秒，上传返回版本冲突（409）后重新读取；其间 iPhone 有一次成功上传。服务端请求处理仅约几十到几百毫秒。这符合本机处理较久期间云端版本变化的情形，但 HTTP 日志不能证明全部空档都是密码计算耗时，也不能据此确认两台手机的账号隔离标识相同。

旧实现每次解密和加密各运行一次 JavaScript PBKDF2，且状态将所有阶段统称为“正在解密、合并并同步”。本次只针对可确认的计算路径和诊断缺口修改，不关闭版本竞争保护，不重置同步库，不更改服务器。

## 兼容性与安全

- 协议仍为 v1，PBKDF2-HMAC-SHA256 **310,000 轮**，32 字节密钥、16 字节盐、12 字节随机 nonce、AES-256-GCM 和原账号 AAD 不变。
- iOS 使用 CommonCrypto，最低系统仍为 **16.1**。Android API 26+ 使用平台 JCA，计算在 Expo 原生异步队列，不占用 JavaScript 线程。
- Web、旧原生二进制或 Android API 24–25 明确不支持时才使用原 Noble 实现。原生计算失败会显示错误，不悄悄重复计算或降级。
- JavaScript 先编码原密码的 UTF-8 字节再跨桥，保留中文、emoji、NUL 和孤立代理项的旧编码行为；不 trim、不 Unicode normalize。
- 不持久缓存派生密钥；可变密码/密钥缓冲区尽力清零。跨语言不可变字符串副本无法保证立即抹除，不宣称绝对内存擦除。
- 不改本机 Keychain/AndroidKeyStore 主密钥，不删除或迁移原密码库，不复制设备私钥到云端。
- 身份、解锁、账号范围、密码变更 epoch、回退保护、三方合并及最多三次 CAS 重试全部保留。

## 可见诊断

同步卡片和设置页显示具体阶段：读取云端、密钥计算/解密、读取本机/合并、加密、上传确认、安全导入。每秒显示本阶段耗时和第几次尝试；超过 30 秒提醒保持前台解锁。只有真正完成安全导入才更新最近成功时间。

这些诊断只存在内存，内容限于固定阶段、计时和重试序号，不输出密码、密钥、密文、连接令牌或记录内容。

## 验证方式

- Node 测试验证 Noble、独立 Node crypto 与原生桥适配间的旧协议互通、中文/emoji/NUL/孤立代理项、错误拒绝及缓冲区清理。这不是手机性能测试。
- JVM 测试验证 Kotlin 算法的固定向量、Unicode 和输入边界；它不代替 Android 真机供应商实现验证。
- GitHub macOS CI 直接编译并执行生产 Swift helper，使用真实 CommonCrypto 校验相同固定向量；随后编译完整 iOS App。
- 两端须覆盖安装本次新包，保留原同步密码和配对。先保持两台 App 前台解锁，分别同步密码库，再检查两台列表是否都包含彼此记录。新成功时间本身不能替代内容核对。
- 若仍不一致，收集两台同步页的账号隔离标识、阶段、耗时和错误截图，不发送任何密码。不要卸载 App、清库或重设原同步密码。

本次不改桌面小组件的 2×2 方形布局、到时显示规则或日期语义，也不改待办同步边界。没有新增实时推送：另一手机停留在页面时仍可下拉刷新或重新进入密码库。
