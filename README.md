# 销客 · 销售工作台 V1

面向手机和电脑的客户/商户工作台，核心目标是“录入快、找人快”。当前实现包含：

- 首页一级全局搜索：姓名、手机号、商户名称、商户编号、终端号
- 300ms 防抖、客户/商户分组、服务端每页最多 20 条
- 客户页姓名/手机号 + 资料状态 + 客户分类 + 录入时间组合筛选
- 移动端本机最近搜索和一键清空
- 搜索结果手机号脱敏，拨打/复制时由服务端再次校验当前登录账号的客户归属
- 客户详情登录后自动显示完整手机号、私有身份证图片和完整银行卡号
- 新增客户可先保存资料待补，并在详情中继续补充或替换身份证图片
- 客户分类统一为：直营、代理、汇来米、收银通
- 客户待办支持关联客户、完成、恢复与删除，并在手机和电脑间同步
- 银行卡号 12–19 位，服务端 AES-256-GCM 加密，不采集 CVV、PIN 或银行卡密码
- Cloudflare D1 保存结构化资料，私有 R2 保存身份证图片；同一登录账号跨设备同步

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

项目的 `.openai/hosting.json` 默认声明 D1 绑定 `DB` 与 R2 绑定 `FILES`。本地开发由 Cloudflare 开发运行时提供本地绑定；正式部署由 Sites 创建并绑定托管资源。首次运行需配置 `SENSITIVE_VIEW_PASSWORD`、32 字节随机的 `BANK_CARD_ENCRYPTION_KEY` 与 `LOCAL_VAULT_UNLOCK_SECRET`。

## 生产配置

复制 `.env.example` 中的键到本地环境或托管平台 Secret：

```text
SENSITIVE_VIEW_PASSWORD=...
BANK_CARD_ENCRYPTION_KEY=...   # 严格 32 字节随机值的标准 Base64
LOCAL_VAULT_UNLOCK_SECRET=... # 严格 32 字节随机值的标准 Base64，同时签名短时敏感图片会话
```

银行卡加密密钥不得使用 `NEXT_PUBLIC_*`，不得提交到 Git。Sites 私有登录向服务端注入稳定的 OpenAI 用户 ID；客户、待办、搜索、详情与文件接口都以该 ID 做服务端归属校验。旧的本机加密档案仍保留本机密码兼容能力。`drizzle/` 中的 D1 迁移会随站点版本发布。

## 安全边界

- 身份证号码、身份证图片内容和银行卡号均不进入搜索索引。
- 普通搜索与普通详情只返回脱敏手机号/上传状态。
- 敏感详情、银行卡修改、证件后补和分类修改都要求登录身份归属校验，响应使用 `private, no-store`。
- 身份证图片位于私有 R2 bucket，只在验证通过后通过约 5 分钟的 HttpOnly 会话读取，不生成公开 URL。
- 银行卡完整卡号仅以与客户 ID 绑定的 AES-GCM 密文保存；明文字段只保留尾号。
- 密码只存在页面组件内存，敏感详情 5 分钟自动隐藏；不会写入 localStorage、URL 或分析日志。
- 本机模式使用随机 AES-256-GCM 主密钥独立加密手机号、身份证图片与银行卡号；短密码还必须结合服务器下发的高熵解锁秘密才能解密，复制 IndexedDB 无法仅靠枚举六位密码离线解锁。
- 本机搜索只保存姓名、脱敏手机号、状态、时间和经过独立 HMAC 密钥计算的手机号片段索引；不保存明文手机号索引。完整资料解锁与图片 Object URL 会在绝对 5 分钟后统一撤销。
- 本机加密只能保护静态浏览器存储，不能抵御已在同源页面执行的恶意脚本；生产仍需严格 CSP、XSS 防护与私有站点登录。

