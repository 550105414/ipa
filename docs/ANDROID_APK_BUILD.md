# 工作台 Android APK

安卓和 iPhone 使用同一份 Expo SDK 55 / React Native / TypeScript 源码。安卓包名固定为 `com.xiaoke.salesworkspace`；当前 1.6.0，versionCode 15。此版修复密码库同步，配套 iPhone build 13，最低 iOS 16.1 不变；保留 build 14 的正方形待办小组件。

## 安装与使用

下载已签名的 `CardWorkbench-1.6.0-build15.apk`，在安卓设备允许当前浏览器或文件管理器“安装未知应用”后覆盖安装，不要先卸载，以保留本机记录。无需 Google Play 或付费开发者会员。首次打开需要先设置设备锁屏密码/PIN/指纹，通过系统身份验证解锁。

在“计划 → 锁屏提醒”允许通知。Android 13 及以上需要通知授权；Android 12 及以上的精确提醒需要允许“闹钟和提醒”。未授权精确提醒时安全降级，系统省电、强行停止和厂商后台限制可能造成延迟，不能保证强制亮屏或绕过勿扰模式。

长按桌面，进入“小组件”，添加“工作台待办”。添加、编辑和完成待办会更新本机快照；只有已到约定时间的待办会进入小组件，App 内仍可提前查看。日期型从当天零点显示；指定时分的待办从指定时间显示。小组件可调整尺寸，内容过多时点击进入 App 查看。

默认请求 2×2 网格，并采用紧凑的标题、行距与留白。build 14 将透明的桌面占位与白色卡片分离，白卡按可用宽高中较短的一边保持正方形并居中，避免在小米偏高的 2×2 网格内拉成竖长方形。行数按白卡内部尺寸计算，而不是按透明占位的高度计算。Android 12 及以上优先使用桌面提供的实际尺寸；旧系统或没有实际尺寸信息的桌面使用尺寸范围回退，最终占位与文件夹的像素对齐仍需真机确认。

放不下的完整任务行通过数量入口提示，不强行裁切显示。仍可长按放大。旧桌面组件的占位由桌面保存，覆盖升级不会强制把已放置的 3×2 缩小：请只移除旧桌面组件，再重新添加 2×2，不要卸载 App。

### 小米添加入口与推荐页

本版是标准 Android AppWidget。小米系统可从小组件中心的“搜索 → 安卓小部件”找到它，具体入口名称随桌面版本变化。它不等于已获审核的小米小部件，不能靠 APK 设置强制进入默认推荐页。

根据[小米官方提交指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1588)，进入小米小部件中心需要适配其规范，先使 App 通过应用商店审核，再提交小部件审核；首次需联系平台开通入口。审核通过也不代表取得默认推荐页的固定推荐位置。本次没有代用户注册账号、同意平台协议、发送联系邮件或提交商店审核。

小组件的到时刷新会在设备重启、系统时间/时区变化和应用覆盖更新后恢复排程。Android 无精确闹钟权限或系统限制后台时，刷新可能延迟。日期型系统通知按预定时的本地时间排程；更换时区后请打开 App 刷新，以便重新排程提醒。

## 跨设备数据

每台设备应分别配对同一个工作台账号，不要复制另一台手机的设备令牌。客户资料继续使用现有受保护服务。全部待办字段和密码库使用独立同步密码加密后同步；同步密码在 App 内设置，不要发到聊天或提交至 Git。

必须先在更新后的 iPhone 版完成首次全量同步，再在安卓配对、输入相同同步密码并同步。旧 iPhone 版不会自动导出仅存在本机的密码库或完整待办元数据。客户照片/证件资料由现有云端接口读取，不放进桌面小组件。

两台手机都离线完成同一个重复待办时，可能各生成一条不同的下一期；系统会保留两边记录并明确停止导入，需核对后选择保留的子待办，不会擅自删除用户编辑。同步密码丢失时无法由服务端解密旧密文；请保留原手机及密码，不要先卸载 App。

## 手动构建

GitHub → Actions → **Build Android APK** → Run workflow。工作流只允许手动触发，普通 Git push 不会打包。

流程：Node / Java 17 → npm ci → TypeScript、lint、tests、Expo 检查 → Android Prebuild → Gradle Release、原生模块单元测试与 lint → 正式签名 → APK 签名/包名/版本/校验值检查 → 上传 APK 与构建日志。没有使用 EAS 或 Expo 云端构建。

需要以下两个 GitHub Actions Secrets：

- `ANDROID_KEYSTORE_BASE64`：固定发行 PKCS12 私钥库的 Base64。
- `ANDROID_KEYSTORE_PASSWORD`：私钥库和私钥密码。

密钥别名固定为 `cardworkbench`，证书 SHA256 固定在工作流中，避免误用其他签名。不会把密钥、密码或真实 Secret 写进源码和构建日志。只上传 APK 和公开构建日志，不上传私钥库。

下载工作流中的 `CardWorkbench-Android-<运行号>`，解压后获取 APK；日志在同次运行的 `CardWorkbench-Android-logs-<运行号>`。Artifacts 保留 7 天；本机交付文件优先保存在 D 盘。

## 签名保管

本次固定发行密钥与 Windows 账户加密的密码备份保存在 `D:/Codex/secrets/CardWorkbenchAndroid-20261028/`，该目录已移除继承权限，只允许当前账户及 SYSTEM。密码备份受 Windows DPAPI 保护，不能仅复制到另一台电脑就解密。GitHub 中只保存加密 Secrets。

后续更新务必继续使用同一私钥签名。不要删除或重新生成私钥；否则已安装用户不能直接覆盖升级。不要先卸载旧 App，以免删除未同步的本机记录。

## 验证边界

宿主 JVM 测试不等于 AndroidKeyStore 或手机实测。只有成功的正式 Gradle 构建和 APK 静态检查才能确认生成可安装产物；还需在实际安卓设备检查系统解锁、通知权限、锁屏提醒、桌面小组件和两端同步。不能把 iPhone 的 IPA、开发服务二维码或 Expo Go 当作 APK。
